# 省钱策略手册

第 6 步「组合试算」的决策依据。核心命题：**同一顿饭，在券 / 积分 / 活动之间选哪条路最省。**

---

## 1. 三条省钱线

| 线 | 资产 | 典型玩法 | 适用时机 |
|---|---|---|---|
| **A 券线** | 麦麦省券 + 卡包券 + 门店可用券 | 固定价券（9.9 元冰美式）、买一送一、免费小食 | 用户有券且想吃的正好命中 |
| **B 积分线** | 积分商城券 + 积分抽奖 | 100 积分换 9.9 元小食券；24 积分抽 3 元券 | 用户积分可用（`availablePoint` > 0） |
| **C 活动线** | 营销日历 + 麦金卡/学生卡 | 9.9 元早餐两件套、四件套 29 元起 | 当前时段有强力度活动 |

**优先顺序不是固定的**，取决于：这单想吃什么、有哪些资源在手、活动是否覆盖该品类。永远用 `calculate-price` 实测三条线的实付再下结论。

---

## 2. 券的价值排序与叠加规则

### 2.1 按「确定性收益」排序（价值从高到低）
1. **免费券**（收益 = 单品全额，如「免费脆薯饼」）
2. **买一送一 / 第二份半价**（收益随数量放大，适合多人或囤货）
3. **固定价券**（如「9.9 元中杯冰美式」，收益 = 原价 − 9.9）
4. **满减 / 折扣券**（收益取决于订单额，需要凑单）

### 2.2 叠加规则（重要）
- **一商品一券**：同一商品通常只能用一张券，多张券不可叠加在同一件商品上。
- **券 vs 活动套餐**：活动的「套餐价」本身已是折后价，一般**不可再叠券**；二者通常**二选一**——这正是 A 线与 C 线的分水岭。
- **需分别试算**：不要凭经验断言「能叠」。把「用券」「走套餐」两种 items 组合各跑一次 `calculate-price`，用实测结果说话。

### 2.3 凑单判断
满减券要有凑单价值判断：**加购金额 < 满减额 → 值得凑**；否则不凑。
> 例：满 30 减 8，当前 ¥25，加一份 ¥6 小食 → 实付 25+6−8 = ¥23，比原 ¥25 更便宜且多一份小食 → 值得凑。

## 3. 积分价值折算

### 3.1 兑换率公式
```
兑换率(积分/元) = 商品所需积分 ÷ 商品面值
```
用 `mall-points-products` 的真实数据算（见 `mcp-tools.md` 第 4.5 节样例）：

| 商品 | 积分 | 面值(元) | 兑换率 | 结论 |
|---|---|---|---|---|
| 6.9元可乐麦炫酷 | 50 | 6.9 | ≈7.2 | **最优** |
| 3.9元圆筒冰淇淋 | 100 | 3.9 | ≈25.6 | 较优 |
| 9.9元指定小食任选 | 100 | 9.9 | ≈10.1 | **优** |
| 10.9元指定小食任选 | 200 | 10.9 | ≈18.3 | 一般 |
| 21.9元巨无霸可乐组合 | 800 | 21.9 | ≈36.5 | 偏贵 |

**兑换率越低越划算。** 军师应优先推荐低兑换率商品。

### 3.2 积分该换券还是抽奖？
- **换券**：收益确定，按 3.1 选兑换率最低的。
- **抽奖**：收益是期望值，有方差。用第 4 节估算。
- 判断规则：若能找到兑换率 ≤ 8 的券，通常**换券优于抽奖**；否则再看抽奖期望。

### 3.3 兑换限制
- `status`：1 仓库中 / 2 上架 / 3 售罄 / 4 下架 / 5 预热 —— **只有上架且在 `upTime`~`downTime` 窗口内才能兑**。
- `spuCategory=1` 虚拟券、`=2` 实物（实物需 `addressId`）。
- `shopId=2` 走 `mall-create-order`；`shopId=5` 的派对走 `party-order-create`。

## 4. 抽奖 ROI 估算

`query-lottery-info` 给出单次成本与奖池。用**公开奖品的名义价值 × 中奖概率**估期望，与单次积分成本比。

实测样例：单次 **24 积分**，奖池含「下单立减 3 元券」「麦旋风 5 折券」「30 积分」等。

粗算示例（仅结构性演示，实际概率以活动公示为准）：
- 假设「3 元券」概率 p≥30% → 期望 ≈ ¥0.9+，而 24 积分按兑换率 ≈7 积分/元折算仅值 ¥3.4 面值。
- 结论口径：**抽奖适合"积分即将过期、且没有合适券可换"时用来博一下**；积分够换明确好券就不要赌。

**硬约束**（务必遵守）：
- 只能依据 `drawDecision.resourceEligible` 判断能否抽，禁止用 `availableTimes` 为 0 自行推断。
- 调用前必须展示 `drawDecision.nextConsumption` 文案并获用户明确确认。
- `fallbackConsumption` 非 null 时，需说明「先消耗次数，次数用完后改为消耗积分」。

---

## 5. 过期资源优先原则

拿到 `query-my-account` 后，若 `currentMouthExpirePoint` > 0，**优先推动用户本月用掉**——过期积分为零价值。

同理，`query-my-prizes` 里状态为「可用」且带时间提醒的奖品券，优先安排进方案。

---

## 6. 决策树

```
用户要吃麦当劳
├─ availablePoint > 0 或 currentMouthExpirePoint > 0 ?
│   ├─ 是 → 查 mall-points-products，找兑换率 ≤ 8 的券
│   │        ├─ 有且命中想吃的 → 走【B 积分线】（吃掉即将过期积分）
│   │        └─ 没有 / 不命中   → 评估抽奖 ROI（第 4 节）
│   └─ 否 → 跳过积分线
├─ campaign-calendar 当前有覆盖该品类/时段的活动 ?
│   └─ 是 → 走【C 活动线】试算（如 9.9 早餐、四件套 29 元起）
├─ query-store-coupons 有可用券 ?
│   └─ 是 → 走【A 券线】试算（免费券 > 买一送一 > 固定价券 > 满减）
└─ 三线各跑一次 calculate-price → 比实付/省额/省率 → 出方案卡
```

## 7. 反模式（别做这些）

- ❌ 不试算就断言"用券更便宜"或"券和套餐能叠加"。
- ❌ 用户积分不可用时仍推荐积分兑换。
- ❌ 把「卡包有券」等同于「这单能用券」。
- ❌ 为了凑满减硬加用户不需要的东西。
- ❌ 把所有可领券一股脑列给用户，不做与本单的相关性筛选。
